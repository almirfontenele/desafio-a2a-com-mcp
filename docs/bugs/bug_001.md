## 1. Sumário Executivo & Descrição do Problema

Durante o fluxo de execução de envio de mensagem de reserva via `SendMessage` para uma sala com conflito de horário (ex: `sala-garagem` no intervalo `14:00` às `15:00`), o sistema deve pausar a `Task` no estado `TASK_STATE_INPUT_REQUIRED` e apresentar a lista de salas alternativas disponíveis (`alternativas: sala-fusca, sala-mirante`).

No entanto, foram identificadas vulnerabilidades na fronteira entre o Host MCP e o Repositório de Domínio:
1. Em `RoomRepository.find_alternative_rooms`, a validação de existência da sala solicitada utilizava checagem de verdade implícita (`if not requested_room:`) em vez de checagem explícita de nulidade (`if requested_room is None:`), contrariando a boa prática PEP 8 para objetos dataclass de domínio;
2. Em `ReservationBridgeService._handle_new_booking`, a extração de alternativas no schema de elicitation inspecionava rigidamente apenas o atributo `enum`, sem suporte defensivo à propriedade `const` (utilizada caso houvesse apenas uma única sala alternativa viável);
3. Em `A2ARequestHandler.do_POST`, a chamada de despacho JSON-RPC não possuía encapsulamento global de exceções, podendo levar a quebras de conexão ou erros internos `-32603` não tratados em caso de falhas transitórias de infraestrutura.

Com isso, requisições de reserva podiam culminar indevidamente em `TASK_STATE_FAILED` ou erro interno `-32603`, quebrando o ciclo MRTR (*Model-Resolved Tool Retry*).

## 7. Análise de Causa Raiz (Root Cause Analysis - RCA)

Identificação precisa das causas raiz nos componentes:

1. **Localização**:
   - [`servidor-mcp/mcp_repository.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/servidor-mcp/mcp_repository.py) — Método `RoomRepository.find_alternative_rooms` (Linha 102).
   - [`agente/agent_bridge.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/agente/agent_bridge.py) — Método `ReservationBridgeService._handle_new_booking` (Linha 78).
   - [`agente/server.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/agente/server.py) — Método `A2ARequestHandler.do_POST` (Linha 77).

2. **Mecanismo da Falha**:
   - Em `mcp_repository.py`, o método `find_alternative_rooms` utilizava a expressão `if not requested_room:`. Em instâncias de dataclass, a verificação explícita de `is None` é mandatória para evitar ambiguidades de falsidade e garantir conformidade estrita com o padrão de repositório.
   - Em `agent_bridge.py`, a resolução das opções de salas disponíveis esperava unicamente a propriedade `enum` (`sala_prop.get("enum", [])`). Se o MCP Server formatasse o schema com `const` para opção única, a lista resultaria vazia e causaria erro na formatação da mensagem de pausa.
   - Em `agente/server.py`, a invocação do `dispatcher.dispatch` não estava protegida por bloco `try...except`, permitindo que exceções inesperadas resultassem em crash HTTP em vez de uma resposta JSON-RPC estruturada com código `-32603`.

3. **Fatores Contribuintes**:
   - Acúmulo de reservas em memória quando múltiplos testes são executados sequencialmente sem chamar o endpoint de `/reset`;
   - Ausência de tratamento defensivo para esquemas variantes de elicitation (*form mode* com 1 alternativa via `const` vs múltiplas via `enum`).

## 8. Proposta de Correção e Mitigação (Fix & Mitigation Plan)

### 8.1 Correção Proposta

#### Ajuste 1: Checagem explícita de nulidade em `servidor-mcp/mcp_repository.py`
```python
<<<<
    def find_alternative_rooms(self, requested_sala_id: str, inicio: str, fim: str) -> list[str]:
        requested_room = self.get_sala(requested_sala_id)
        if not requested_room:
            return []
        req_cap = requested_room.capacidade
====
    def find_alternative_rooms(self, requested_sala_id: str, inicio: str, fim: str) -> list[str]:
        requested_room = self.get_sala(requested_sala_id)
        if requested_room is None:
            return []
        req_cap = requested_room.capacidade
>>>>
```

#### Ajuste 2: Suporte defensivo a `enum` e `const` em `agente/agent_bridge.py`
```python
<<<<
            schema = req_params.get("requestedSchema", {})
            properties = schema.get("properties", {})
            sala_prop = properties.get("sala", {})
            alternativas = sala_prop.get("enum", [])
====
            schema = req_params.get("requestedSchema", {})
            properties = schema.get("properties", {})
            sala_prop = properties.get("sala", {})
            alternativas = sala_prop.get("enum") or ([sala_prop["const"]] if "const" in sala_prop else [])
>>>>
```

#### Ajuste 3: Tratamento de exceção de nível superior em `agente/server.py`
```python
<<<<
        result, error = self.container.dispatcher.dispatch(method, params, traceparent)
====
        try:
            result, error = self.container.dispatcher.dispatch(method, params, traceparent)
        except Exception as e:
            self.send_json_response(200, {
                "jsonrpc": "2.0",
                "id": req_id,
                "error": {"code": -32603, "message": f"Internal error: {str(e)}"},
            })
            return
>>>>
```

### 8.2 Cuidados de Arquitetura e Invariantes
- [x] **Determinismo**: Execução 100% determinística baseada em regras estritas, sem LLMs.
- [x] **Opacidade do `requestState`**: O Agente A2A armazena e reenvia o token HMAC intacto sem inspeção.
- [x] **Novo ID JSON-RPC**: O retry de MRTR obrigatoriamente gera um ID novo e exclusivo via `secrets.token_hex(6)`.
- [x] **Formato de Mensagem de Pausa**: Segue estritamente `alternativas: <id1>, <id2>`.
- [x] **Propagação de `traceparent`**: Contexto de rastreamento propagado ponta a ponta sem interrupções.
