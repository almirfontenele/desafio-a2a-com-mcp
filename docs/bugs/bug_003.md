## 1. Sumário Executivo & Descrição do Problema

Durante a auditoria de conformidade pós-implementação do [BUG-002](file:///home/almir/projetos/desafio-a2a-com-mcp/docs/bugs/bug_002.md), foram identificadas duas inconsistências críticas relativas às exigências formais do desafio e à arquitetura interna do Servidor MCP:

1. **Restrição Inadequada e Versão Solta no [`pyproject.toml`](file:///home/almir/projetos/desafio-a2a-com-mcp/pyproject.toml)**:
   A dependência do SDK MCP foi declarada como `"mcp>=1.2.0,<2.0.0"`. Essa declaração apresenta dois problemas graves:
   - **Versão solta (não pinada)**: Viola a regra do desafio de *"versões travadas no package.json ou no pyproject.toml"*;
   - **Exclusão mandatória da v2**: A restrição `<2.0.0` bloqueia ativamente a instalação de qualquer versão 2.x do SDK MCP, forçando o ambiente a instalar versões legadas (especificamente a versão `1.12.4`), violando o requisito explícito de utilizar o *"SDK oficial do MCP na v2, alinhado à revisão 2026-07-28 da spec"*.

2. **Integração Cosmética / Despacho Manual no [`servidor-mcp/server.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/servidor-mcp/server.py)**:
   Embora o arquivo instancie a classe `Server` (`mcp.server.lowlevel.Server`) e declare decoradores em `_register_mcp_handlers`, a rota HTTP `POST /mcp` não delega o processamento da requisição JSON-RPC à instância do SDK. Em vez disso, o método `post_mcp` inspeciona e roteia o payload manualmente através de condicionais procedurais (`if method == "tools/list": ... elif method == "resources/read": ... elif method == "tools/call": ...`), tornando o objeto `Server` um artefato inerte e não operacional na pipeline real de execução.

## 2. Componentes e Fronteiras de Protocolo Afetados

Subsistemas diretamente impactados pelo defeito:

- [x] **Manifesto de Dependências (`pyproject.toml`)**:
  - Travar o pacote `mcp` em uma versão específica e exata da v2 (ex: `mcp==2.3.0` ou versão estável 2.x suportada).
  - Assegurar a reprodutibilidade exata em ambientes de desenvolvimento, validação e contêineres Docker.
- [x] **Servidor MCP (`servidor-mcp/server.py`)**:
  - Eliminar o tratamento manual do despacho JSON-RPC no endpoint `/mcp`.
  - Conectar de forma efetiva o ciclo de vida e a resolução de chamadas ao `Server` do SDK oficial MCP.
  - Preservar os requisitos mandatórios de conformidade:
    - Verificação de cabeçalhos e metadados `_meta` com retorno HTTP 400 (`-32602`);
    - Logging padronizado no `sys.stderr` (`[MCP-SERVER] POST <method> id=<id> traceparent=<tp>`);
    - Mecanismo de estado selado `requestState` e assinatura HMAC-SHA256 para o ciclo MRTR;
    - Endpoint auxiliar `POST /reset` para restauração do estado em suítes de testes.
- [x] **Suíte de Validação (`validador/validar.py`)**:
  - Garantir a manutenção de 100% de aprovação (36/36 verificações de conformidade).


## 5. Comportamento Observado vs. Comportamento Esperado

### 5.1 Comportamento Observado (Actual Behavior)
- O manifesto [`pyproject.toml`](file:///home/almir/projetos/desafio-a2a-com-mcp/pyproject.toml) define uma faixa aberta que bloqueia a v2 (`mcp>=1.2.0,<2.0.0`).
- O resolvedor de pacotes instalou a versão `1.12.4`.
- A instância de `Server` é criada e decorada com manipuladores assíncronos que nunca são acionados durante requisições ao endpoint `/mcp`.
- O endpoint `/mcp` processa manualmente as chamadas JSON-RPC.

### 5.2 Comportamento Esperado (Expected Behavior)
- O manifesto [`pyproject.toml`](file:///home/almir/projetos/desafio-a2a-com-mcp/pyproject.toml) deve fixar uma versão exata da v2 (`mcp==2.x.x`).
- O ambiente deve operar com o SDK oficial MCP na versão 2.
- O endpoint `/mcp` deve utilizar efetivamente os mecanismos providos pelo SDK oficial do MCP para manipulação e despacho dos métodos (`tools/list`, `tools/call`, `resources/read`), mantendo a compatibilidade estrita com os testes de conformidade.

## 7. Análise de Causa Raiz (Root Cause Analysis - RCA)

1. **Localização**:
   - [`pyproject.toml`](file:///home/almir/projetos/desafio-a2a-com-mcp/pyproject.toml): Linha 12 (`"mcp>=1.2.0,<2.0.0"`).
   - [`servidor-mcp/server.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/servidor-mcp/server.py): Função `post_mcp` e classe `MCPServiceContainer`.

2. **Mecanismo da Falha**:
   - Na implementação do [BUG-002](file:///home/almir/projetos/desafio-a2a-com-mcp/docs/bugs/bug_002.md), buscou-se manter conformidade estrita com os contratos HTTP ponta a ponta exigidos pelo `validador.py` (erros com HTTP 400 em caso de ausência de `_meta`, formatação exata de retornos com HMAC etc.). Para garantir aprovação imediata das 36 asserções sem efeitos colaterais de serialização interna do SDK, o despacho JSON-RPC em `/mcp` foi mantido de forma manual, enquanto a instância `Server` foi apenas declarada sem integrar a cadeia de execução.
   - Concomitantemente, a especificação da dependência no `pyproject.toml` utilizou um limite defensivo `<2.0.0` que impediu a atualização para a versão 2 do SDK exigida pelas especificações do projeto.

## 8. Plano de Ação e Solução Proposta

1. **Atualização e Fixação de Versão no [`pyproject.toml`](file:///home/almir/projetos/desafio-a2a-com-mcp/pyproject.toml)**:
   - Alterar a dependência para uma versão exata da v2 (ex: `mcp==2.3.0`).
   - Reinstalar as dependências no ambiente virtual via `pip install -e .`.

2. **Refatoração do Servidor MCP ([`servidor-mcp/server.py`](file:///home/almir/projetos/desafio-a2a-com-mcp/servidor-mcp/server.py))**:
   - Integrar a execução do `Server` oficial nas operações de ferramentas e recursos expostos no endpoint `/mcp`.
   - Assegurar que os validadores de protocolo (`_meta`, `protocolVersion`, `clientCapabilities`), os logs obrigatórios em `sys.stderr` e a gestão do `requestState` HMAC funcionem em perfeita consonância com o SDK oficial e com o transporte HTTP.

3. **Verificação e Validação Automatizada**:
   - Executar a suíte de testes de conformidade `python3 validador/validar.py --agente http://localhost:7300 --mcp http://localhost:7301` e comprovar a aprovação de 36/36 verificações.
